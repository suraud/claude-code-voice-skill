# 音声会話

VoiceMode(MCP サーバー)と、Mac 内で動く Whisper(音声認識)、Kokoro(読み上げ)を使って、利用者と声で会話する。入れ方と設定の理由は、このスキルのリポジトリの `README.md` と `docs/セットアップ手順.md` にある。

## 引数

| 引数 | 動作 |
|---|---|
| なし、または `on` | サービスを起動し、音声会話を始める。利用者は発言を「以上」で締める |
| `off` | サービスを停止する。ログイン時の自動起動も解除する |
| `status` | サービスの状態を表示する |

## 手順

### 1. サービスを切り替える

```
~/.claude/skills/10-voice/scripts/voice.sh on
```

`off`、`status` も同じスクリプトに渡す。`on` は起動の前に、接続先が Mac 内だけであること、OpenAI の API キーがないこと、待ち受けが `127.0.0.1` だけであることを確かめる。確認に失敗したら起動せずに止まるので、出力をそのまま利用者に伝える。設定を緩めて回避しない。

### 2. 会話をする

1 往復を、次のコマンド 1 つで行う。読み上げと聞き取りの両方を、専用のスクリプトが担う。制限時間は 600000 ミリ秒にする。出力を利用者の発言として扱う。

```
~/.claude/skills/10-voice/scripts/voice.sh listen --say '読み上げる文'
```

読み上げる文は単一引用符で囲む。文の中に単一引用符を入れない。

- スクリプトは先にマイクを開き、それから Mac 内の Kokoro で読み上げる。読み終わると合図の音が鳴り、聞き取りに入る
- 聞き取りは、利用者が「以上」と言うまで終わらない。考えて黙っている間も切れない。「以上」は出力から除かれる
- 読み上げ中に利用者が話すと、読み上げを止めて聞き取りに入る(割り込み)。出力の先頭に `[割り込み: …]` と、伝わったおよその範囲が付く。範囲は再生時間からの見積もりなので、それより後ろは伝わっていない前提で応じ、必要なら言い直す
- 利用者が「ミュート」とだけ言うと、マイクを閉じて終わる。出力に `[ミュート: …]` と付く。このあとは声で呼びかけず、画面に「再開するときは `/10-voice` と入力してください」と書いて待つ
- 出力の最後に `[打ち切り: …]` と付いていたら、「以上」が聞こえないまま終わっている(60 秒の無音、または 8 分の制限)。聞き取れた分を声で伝え、続きがあるかを尋ねる
- 私が作業している間は、マイクは閉じている。利用者の声は届かない
- 複数のセッションで同時に使うと、自動で順番待ちになる。一度に 1 つのセッションだけが話して聞く。別のセッションから切り替わったときは、スクリプトが読み上げの最初にプロジェクト名(作業フォルダの名前)を名乗る。自分で名乗りを足さない
- 出力が `[順番待ち: …]` だけだったら、ほかのセッションが会話中で、読み上げていない。同じコマンドをもう一度実行する

最初の一言で、声が聞こえているかを確かめ、「話し終わったら『以上』と言ってください」と伝える。

`mcp__voicemode__converse` は会話に使わない。聞き取りは 1 秒の無音で切れ、読み上げには割り込めないため。

### 3. 会話を終える

利用者が「終わり」「画面に戻る」と言ったら、音声での呼びかけをやめる。サービスを止めるかどうかを尋ね、止める場合は `voice.sh off` を実行する。起動中は 3GB ほどメモリを使う。

## 話し方

- 1 回の発話は短くし、質問は 1 つずつにする。長い発話は聞き返せないため
- 表、コード、パス、URL、長い一覧は読み上げない。ファイルに書いて `open` で開き、声では「ファイルを開きました」と要点だけを伝える。会話の途中で画面に書いた文章は、利用者に見えていないことがある(聞き取りのコマンドを実行している間は表示が進まない)。一時的な内容は、スクラッチパッドに md で書いて開く
- 英単語や記号は、読み上げ用の文ではカタカナや日本語に直す(例:「スクリプト」「三ギガ」)。日本語の声は英字の読みが不安定なため
- 承認が必要な操作(環境の変更、削除、外部への送信、作業フォルダの外への書き込み)は、対象と影響を声で伝えて、返事を聞いてから実行する
- 認識結果が不自然なとき、承認の返事があいまいなときは、推測で進めずに聞き返す。音声認識には誤変換がある(例:「ホーム」が「フォーム」になる)
- 聞き取りの出力が打ち切りの表示だけだったら、もう一度呼びかける。続く場合は画面で状況を伝える
- 「三つ以上」「これ以上」のように、数量や比較に続く「以上」では終わらない。認識結果が数字の直後の「以上」で終わっていて打ち切りになった場合は、終わりの合図だった可能性がある
- 会話の途中で仕組み(スクリプト、設定、スキル)に手を加えたときは、何を変えたかを声でも一言伝える。画面に書くだけにしない。それ以外の途中経過は読み上げなくてよい

## 守ること

- `tts_provider` に `openai` を指定しない。`OPENAI_API_KEY` を設定しない。接続先にローカル以外の URL を加えない。会話の音声を Mac の外へ出さないため
- `voicemode connect`(外部サービスへのログイン機能)を使わない
- VoiceMode は版を固定して入れてある。更新するときは利用者に確認し、更新後に `voice.sh on` で設定を確かめ直す

## 注意点

- 利用者のイヤホンは、話していない間は完全な無音を送ってくる。無音の録音だけでマイクの故障と判断しない
