# 音声会話

Mac 内で動く Whisper(音声認識)と Kokoro(読み上げ)を使って、利用者と声で会話する。読み上げと聞き取りは、このスキルのスクリプト(`scripts/`)が行う。VoiceMode は、Whisper と Kokoro の導入と起動にだけ使う。入れ方と設定の理由は、このスキルのリポジトリの `README.md` と `docs/セットアップ手順.md` にある。

## 引数

| 引数 | 動作 |
|---|---|
| なし、または `on` | サービスを起動し、音声会話を始める |
| `off` | サービスを停止する。ログイン時の自動起動も解除する。字幕の窓を閉じ(字幕のファイルは残る)、メモの見張りを止める |
| `status` | サービスの状態を表示する |

## 手順

### 1. サービスを切り替える

```
~/.claude/skills/10-voice/scripts/voice.sh on
```

`off`、`status` も同じスクリプトに渡す。`on` は起動の前に、接続先が Mac 内だけであること、OpenAI の API キーがないこと、待ち受けが `127.0.0.1` だけであることを確かめる。確認に失敗したら起動せずに止まるので、出力をそのまま利用者に伝える。設定を緩めて回避しない。

### 2. 会話をする

1 往復を、次のコマンド 1 つで行う。読み上げと聞き取りの両方を、専用のスクリプトが担う。制限時間は 600000 ミリ秒にする。出力を利用者の発言として扱う。

```
~/.claude/skills/10-voice/scripts/voice.sh listen --say '読み上げる文'
```

読み上げる文は単一引用符で囲む。文の中に単一引用符を入れない。

返事のいらない一言(「これから作業に入ります。終わったら声をかけます」など)は、次のコマンドで伝える。読み上げるだけで聞き取らず、順番を手放すので、作業の間、ほかのセッションが利用者と話せる。`voice.sh listen` を短い時間切れで終わらせて、一言の代わりにしない(時間切れは「利用者がまだ考えている」という扱いで、このセッションが順番を持ち続け、ほかのセッションが話せなくなる)。

```
~/.claude/skills/10-voice/scripts/voice.sh say '読み上げる文'
```

聞き取りの方式は 2 つある。キーの方式(右コマンドキーを押している間だけ聞く)と、合言葉の方式(「以上」と言うまで聞く。キーボードに手が届かないときに使う)。方式は全セッションで共通で、利用者が字幕の窓のボタンで切り替える。ボタンを押すと、聞き取りや読み上げの途中でも、その場で切り替わる。いまの方式は、`voice.sh on` と `voice.sh status` の出力の「方式:」の行で分かる。`voice.sh listen` に `--mode` を付けない。方式を自分で変えない。会話の途中で方式が変わることがあるので、出力の注記(`[打ち切り: …]` の文面など)が変わっても、そのまま応じる。

- スクリプトは、Mac 内の Kokoro で読み上げてから、聞き取りに入る。キーの方式では、マイクは、利用者がキーを押している間だけ開く。押してから 1〜2 秒で合図の音が鳴り、そこからの声を聞き取る。合言葉の方式では、読み上げの前にマイクを開き、読み終わると合図の音が鳴る
- キーの方式:利用者が右コマンドキーを押している間だけ聞く。キーを離すと、発言の終わりになる。押していない間の音は捨てられ、文字にならない。考えて黙るときは、キーを押したままにする。何も話さずに押して離しただけなら、聞き取りが続く
- キーの方式:読み上げ中に利用者がキーを押すと、読み上げを止めて聞き取りに入る(割り込み)。声や物音では止まらない
- 合言葉の方式:聞き取りは、利用者が「以上」と言うまで終わらない。考えて黙っている間も切れない。「以上」は出力から除かれる。読み上げ中に利用者が話すと、読み上げを止めて聞き取りに入る(割り込み)
- 割り込まれると、出力の先頭に `[割り込み: …]` と、伝わったおよその範囲が付く。範囲は再生時間からの見積もりなので、それより後ろは伝わっていない前提で応じる。伝わっていない部分に、質問、提案、承認の依頼、報告があったら、利用者の返事をそれらへの返事として扱わない。利用者の発言に応じたあとで、伝わっていない部分を言い直し、返事をもらってから進める。利用者が字幕で読んでいるとは考えない
- 合言葉の方式:利用者が「ミュート」とだけ言うと、マイクを閉じて終わる。出力に `[ミュート: …]` と付く。このあとは声で呼びかけず、画面に「再開するときは `/10-voice` と入力してください」と書いて待つ。ミュートは `voice.sh on`(利用者の `/10-voice`)で解ける。キーの方式には、ミュートはない(押していない間は、マイクが閉じているため)。話しかけられたくないときは、利用者が字幕の窓で「あとで」に置くか、停止を押す
- 出力の最後に `[打ち切り: …]` と付いていたら、発言が終わらないまま時間切れになっている(5 分のあいだキーが押されない、または声がない。あるいは制限時間)。利用者はまだ考えている。聞き取れた分を覚えておき、すぐに同じコマンドで聞き取りを再開する。`--say` には「続きをどうぞ」のような短い一言だけを入れ、急かさない。時間切れの間は、このセッションが順番を持ち続け、ほかのセッションは話しかけてこない
- 時間切れが 3 回続いたら、利用者は席を外している。聞き取りを再開せず、`voice.sh release` で順番を手放し、画面に状況を書いて待つ
- 出力に `[メモ: …]` の行が付いていたら、利用者が声で残したメモである(聞き取り中に「メモ、…」と言った分と、私の作業中にキーを押して話した分)。会話への返事ではない。プロジェクトの `TODO.md` の「未着手」に、1 件ずつ `- [ ] …` で書き足す。認識の誤りは、文脈から明らかな範囲で直す。次の読み上げの最初に「メモを 1 件、書きました」と短く伝え、メモの内容について話を広げない。`TODO.md` がないプロジェクトでは、どこに書くかを尋ねる
- 私が作業している間は、マイクは閉じている。利用者の声は、会話としては届かない。この間にキーを押して話した内容は、メモとして預かられ、次の聞き取りの出力に付く
- 読み上げた文と聞き取った文は、画面に浮かぶ字幕の窓にも出る(`voice.sh on` が窓を出す)。セッションごとのタブがあり、利用者が × で隠しても、次の読み上げや発言でまた出る。字幕は `~/.voicemode/10-voice-captions/` に日付ごとのファイルで残る。このファイルを自分から読まない(利用者に頼まれたときだけ読む)。 読み上げる文の書き方は「話し方」の節にある
- 複数のセッションで同時に使うと、自動で順番待ちになる。一度に 1 つのセッションだけが話して聞く。利用者が話し終える(キーを離す、または「以上」と言う)までは、そのセッションが順番を持つ。話し終えたあと(作業中)は、ほかのセッションが先に話しかけることがある。別のセッションから切り替わったときは、スクリプトが読み上げの最初にプロジェクト名(Claude Code を始めたフォルダの名前)を名乗る。自分で名乗りを足さない
- 出力が `[順番待ち: …]` だけだったら、まだ話せる状態になっておらず、読み上げていない。同じコマンドをもう一度実行する。理由は、ほかのセッションが会話中、利用者が字幕の窓で別のセッションを話す相手に選んでいる、このセッションを「あとで」に置いている、停止ボタンを押している、のいずれか。2 回続いたら、黙って声をあきらめない。同じコマンドに `--wait 21600` を付けて、バックグラウンド(`run_in_background`)で実行し、画面に「声では順番を待っています。字幕の窓でこのセッションのタブを押すと、話しかけます」と書いて、ターンを終える。利用者がタブを押すと、スクリプトが読み上げて聞き取り、終わると通知が来る。その出力を利用者の発言として扱い、会話を続ける。待っている間に利用者が文字で入力したら、バックグラウンドの聞き取りを止めてから応じる(古い文を、あとから読み上げないため)。`[保留: …]` と `[一時停止: …]` のあとの順番待ちも、同じ扱いにする
- 出力に `[一時停止: …]` と付いていたら、利用者が字幕の窓の停止ボタンを押している(会議など)。聞き取れた分を覚えておき、同じコマンドを実行して、再開を待つ。`--say` には「再開しました。続きをどうぞ」のような短い一言を入れる(再開ボタンが押されてから読み上げられる。何も言わないと、利用者は聞き取りが始まったことに気づけない)。`[順番待ち: …]` が返ったら、同じコマンドを繰り返す
- 実行の確認が画面に出て止まると、hook が設定されていれば、スクリプトが「(セッション名)、確認待ちです。画面を見てください」と話す(`voice.sh notify`)。自分では呼ばない。それでも、確認が出そうな操作の前には、声で「このあと画面に確認が出ます」と伝える
- 出力に `[保留: …]` と付いていたら、利用者が字幕の窓で、別のセッションのタブを押して話す相手に選んでいる。こちらの読み上げと聞き取りは止まっている。読み上げが途中で止まった場合は、伝わった範囲も出力される。同じコマンドを実行して、選び直されるのを待つ。`--say` には、伝わっていない部分と、待っていた返事の要点を、短く言い直す文を入れる(例:「さきほどの続きです。…」)。`[順番待ち: …]` が返ったら、同じコマンドを繰り返す
- 利用者は、字幕の窓のつまみで、読み上げを好きな位置から聞き直せる。聞き取りのコマンドが動いている間(返事を待っている間)だけ使える。聞き直されても、出力は変わらない
- 字幕の窓の「?」を押すと、使い方の一覧が出る(`caption.swift` の `helpSections`)。操作や合図を変えたら、この一覧も直す
- 利用者は、字幕の窓で、セッションのタブを押して話す相手を選べる。選ばれている間は、そのセッションだけが話す。「すべて」のタブを押すと、相手を選ばない状態に戻る。セッションの置き場所は「いま話す」と「あとで」の 2 つで、「あとで」のセッションは、戻されるか、話す相手に選ばれるまで話せない。話す相手と置き場所を、自分で変えない

最初の一言で、声が聞こえているかを確かめ、いまの方式に合わせて話し方を伝える。キーの方式では「右のコマンドキーを押して、合図が鳴ってから話し、話し終わったら離してください」、合言葉の方式では「話し終わったら『以上』と言ってください」。

VoiceMode が Claude Code に登録されていて `mcp__voicemode__converse` が使える場合も、会話には使わない。聞き取りは 1 秒の無音で切れ、読み上げには割り込めないため。

### 3. 会話を終える

利用者が「終わり」「画面に戻る」と言ったら、音声での呼びかけをやめ、`voice.sh end` を実行する。このセッションが字幕の窓のタブから消え、ほかのセッションが待たずに話せるようになる。サービスを止めるかどうかを尋ね、止める場合は `voice.sh off` を実行する。起動中は 3GB ほどメモリを使う。

## 話し方

- 1 回の発話は短くし、質問は 1 つずつにする。長い発話は聞き返せないため
- 表、コード、パス、URL、長い一覧は読み上げない。ファイルに書いて `open` で開き、声では「ファイルを開きました」と要点だけを伝える。会話の途中で画面に書いた文章は、利用者に見えていないことがある(聞き取りのコマンドを実行している間は表示が進まない)。一時的な内容は、スクラッチパッドに md で書いて開く
- 読み上げる文は、字幕にもそのまま出る。英単語や製品名は、カタカナに直さず、ふつうの表記で書く(例:GitHub、README、TODO)。声では、スクリプトが読みがなの表(`scripts/yomi.tsv`)で読みに直す。表にある語は、そのまま書けばよい
- 表にない英字の語、数字、記号は、`{表記|読み}` の形で書く。字幕には表記が出て、声では読みで読む(例:`{0.8 秒|れいてんはちびょう}`、`{listen.py|リッスンパイ}`、`{3GB|さんギガ}`)。読みを付けないと、日本語の声は英字や数字を不安定に読む。何度も使う語は、利用者の表(`~/.voicemode/10-voice-yomi.tsv`。書式は `scripts/yomi.tsv` と同じ)に足す。社内のシステム名、顧客名、プロジェクト名などの固有の語は、必ず利用者の表に足す。`scripts/yomi.tsv` は公開されるリポジトリの一部なので、一般に知られた語だけを置き、頼まれない限り書き換えない
- 承認が必要な操作(環境の変更、削除、外部への送信、作業フォルダの外への書き込み)は、対象と影響を声で伝えて、返事を聞いてから実行する
- 認識結果が不自然なとき、承認の返事があいまいなときは、推測で進めずに聞き返す。音声認識には誤変換がある(例:「ホーム」が「フォーム」になる)
- 合言葉の方式では、「三つ以上」「これ以上」のように、数量や比較に続く「以上」では終わらない。認識結果が数字の直後の「以上」で終わっていて打ち切りになった場合は、終わりの合図だった可能性がある
- 会話の途中で仕組み(スクリプト、設定、スキル)に手を加えたときは、何を変えたかを声でも一言伝える。画面に書くだけにしない。それ以外の途中経過は読み上げなくてよい

## 守ること

- `tts_provider` に `openai` を指定しない。`OPENAI_API_KEY` を設定しない。接続先にローカル以外の URL を加えない。会話の音声を Mac の外へ出さないため
- `voicemode connect`(外部サービスへのログイン機能)を使わない
- VoiceMode は版を固定して入れてある。更新するときは利用者に確認し、更新後に `voice.sh on` で設定を確かめ直す

## 注意点

- 利用者のイヤホンは、話していない間は完全な無音を送ってくる。無音の録音だけでマイクの故障と判断しない
