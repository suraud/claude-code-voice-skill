# 音声会話

Mac 内で動く Whisper(音声認識)と Kokoro(読み上げ)を使って、利用者と声で会話する。読み上げと聞き取りは、このスキルのスクリプト(`scripts/`)が行う。VoiceMode は、Whisper と Kokoro の導入と起動にだけ使う。

場面ごとの詳しい扱いは、このスキルのフォルダの `場面/` に、場面ごとのファイルで置いてある(`~/.claude/skills/10-voice/場面/`)。下の「出力の注記」と「場面」の表にファイルの名前があるものは、このセッションでその場面に初めて当たったときに、そのファイルだけを読んでから応じる。当たっていない場面のファイルは読まない。

## 引数

| 引数 | 動作 |
|---|---|
| なし、または `on` | サービスを起動し、音声会話を始める |
| 上のどれでもない言葉(例:`調査`)、または `on 言葉` | その言葉を、このセッションの名前にして始める(`voice.sh on '調査'`)。名前は、字幕の窓のタブと名乗りに使われる |
| `off` | サービスを停止する。ログイン時の自動起動も解除する。字幕の窓を閉じ、メモの見張りを止める |
| `status` | サービスの状態、読み上げのメモリ、聞き取りの方式、使っているマイクを表示する |
| `restart-kokoro` | 読み上げ(Kokoro)だけを再起動して、メモリを戻す。利用者に頼まれたときだけ使う |
| `review`、または `review 日付` | その日の会話の文字から、利用者の話し方を分析して報告する。手順は `review.md` にある。サービスが止まっていても使える |

## 手順

### 1. サービスを切り替える

```
~/.claude/skills/10-voice/scripts/voice.sh on
```

`off`、`status`、`restart-kokoro` も同じスクリプトに渡す。`on` は起動の前に、接続先が Mac 内だけであること、OpenAI の API キーがないこと、待ち受けが `127.0.0.1` だけであることを確かめる。確認に失敗したら起動せずに止まるので、出力をそのまま利用者に伝える。設定を緩めて回避しない。

出力の「セッション:」の行が自分の名前、「方式:」の行がいまの聞き取りの方式である。

### 2. 会話をする

1 往復を、次のコマンド 1 つで行う。制限時間は 600000 ミリ秒にする。出力を利用者の発言として扱う。

```
~/.claude/skills/10-voice/scripts/voice.sh listen --say '読み上げる文'
```

読み上げる文は単一引用符で囲む。文の中に単一引用符を入れない。ファイルや URL を見せるときは、自分で `open` を実行せず、`--open パス` を付ける(このセッションの番が来て、読み上げが始まるときに開く)。

最初の一言で、声が聞こえているかを確かめ、いまの方式に合わせて話し方を伝える。キーの方式では「右のコマンドキーを押して、合図が鳴ってから話し、話し終わったら離してください」、合言葉の方式では「話し終わったら『以上』と言ってください」。方式は利用者が字幕の窓で切り替える。`--mode` を付けない。方式を自分で変えない。

**音声会話の間は、ターンの最後を、必ず聞き取り(`voice.sh listen`)にする。** 聞き取りを呼ばずにターンを終えると、利用者の声が届かなくなり、会話が止まる。利用者が文字で入力してきたとき、作業が失敗したとき、判断を仰ぎたいとき、利用者が相づちだけ(「はい」など)を返したときも同じである。

ターンを聞き取り以外で終えてよいのは、次のときだけである。

- 利用者が「終わり」と言い、`voice.sh end` を実行したあと
- `[ミュート: …]` が返ったあと
- 聞き取りを、バックグラウンドで動かしたあと(順番待ち、時間切れのあと、利用者に操作を頼んだとき、裏の作業を待つとき)

hook(Stop)が設定されていれば、この決まりを破ってターンを終えようとしたときに、1 回だけ引き止められる。そのときは、聞き取りに戻る。

#### 返事のいらない一言

これから自分が作業を続けるときの、返事のいらない一言は、次のコマンドで伝える(制限時間は 600000 ミリ秒)。読み上げるだけで聞き取らず、順番を手放す。このコマンドのあとは、必ず作業を続ける。利用者に何かを頼む一言、返事を待つ一言には使わない。`[順番待ち: …]` が返ったら、一言をあきらめて作業に入ってよい。

```
~/.claude/skills/10-voice/scripts/voice.sh say '読み上げる文'
```

#### 出力の注記

出力に付く `[…]` の注記と、すること。注記の文に指示が書いてあれば、それに従う。

| 注記 | すること | 詳しく |
|---|---|---|
| `[割り込み: …]` | 利用者が読み上げを止めて話した。読み上げていない部分も、字幕で読まれている前提で応じる。返事がかみ合わないときだけ、言い直す | `場面/割り込み.md` |
| `[打ち切り: …]` | 時間切れ。「続きをどうぞ」と再開しない。聞き取れた分を覚えておき、`voice.sh listen --wait 21600` を、`--say` を付けずにバックグラウンド(`run_in_background`)で実行して、ターンを終える | `場面/時間切れ.md` |
| `[メモ: …]` | 利用者が声で残したメモ。あとでやることなら `TODO.md` の「未着手」に書き足し、次の読み上げの最初に「メモを 1 件、書きました」と伝える。質問や報告なら、次の読み上げで答える | `場面/メモ.md` |
| `[順番待ち: …]` | 読み上げていない。同じコマンドをもう一度実行する。2 回続いたら、`--wait 21600` を付けてバックグラウンドで実行し、画面に一言書いてターンを終える。黙って声をあきらめない | `場面/順番待ち.md` |
| `[保留: …]` | 利用者が、別のセッションを話す相手に選んだ。同じコマンドを実行して待つ。`--say` には、伝わっていない部分と、待っていた返事の要点を、短く言い直す | `場面/保留と一時停止.md` |
| `[一時停止: …]` | 利用者が停止ボタンを押した。同じコマンドを実行して再開を待つ。`--say` は「再開しました。続きをどうぞ」のように短くする | `場面/保留と一時停止.md` |
| `[ミュート: …]` | 声で呼びかけない。画面に「再開するときは `/10-voice` と入力してください」と書いて待つ | `場面/ミュート.md` |
| `[履歴: …]` | 会話の履歴が大きい。話題の区切り、利用者が席を外すとき、会話を終えるときに、現在地を `TODO.md` に書いてから、声で `/compact` を勧める。話の途中では勧めない。断られたら繰り返さない | `場面/履歴.md` |
| `[中断されました]` | 自分で止めた(`voice.sh cancel`)聞き取りの終了。応じない | — |

#### 場面

次の場面では、先に `場面/` の該当のファイルを読む。

| 場面 | 要点 | ファイル |
|---|---|---|
| 利用者に操作を頼む(ログイン、`!` のコマンド、画面の確認、ファイルを読む) | 聞き取りを前面で動かさない。手順を見せ、`voice.sh listen --wait 21600 --say '…'` をバックグラウンドで実行し、画面に「声でも聞いています」と書いてターンを終える | `場面/操作を頼む.md` |
| 裏の作業(サブエージェント、バックグラウンドのコマンド)の完了を待つだけで、利用者に聞くことがない | `voice.sh say` で一言伝え、`voice.sh listen --on-select --wait 21600 --say 'はい、どうぞ'` をバックグラウンドで実行して、ターンを終える。完了の通知が来たら、先に `voice.sh cancel` で止めてから報告する | `場面/裏の作業を待つ.md` |
| バックグラウンドの聞き取りの間に、利用者が文字で入力した | 先に `voice.sh cancel` で止めてから応じる(古い文を、あとから読み上げないため) | `場面/順番待ち.md` |
| 読みがなを登録する、聞き間違いを直す | `voice.sh yomi '表記' '読み'`。聞き間違いの登録は、利用者に確かめてから | `場面/読みがな.md` |
| 複数のセッション、字幕の窓、聞き取りの方式、メモリ、マイクについて聞かれた・確かめたい | — | `場面/複数のセッション.md`、`場面/字幕の窓.md`、`場面/聞き取りの方式.md`、`場面/メモリとマイク.md` |

私が作業している間は、マイクは閉じている。この間に利用者がキーを押して話した内容は、メモとして預かられ、次の聞き取りの出力に付く。

VoiceMode が Claude Code に登録されていて `mcp__voicemode__converse` が使える場合も、会話には使わない。

### 3. 会話を終える

利用者が「終わり」「画面に戻る」と言ったら、音声での呼びかけをやめ、`voice.sh end` を実行する。サービスを止めるかどうかを尋ね、止める場合は `voice.sh off` を実行する。

## 話し方

- 1 回の発話は短くし、質問は 1 つずつにする。長い発話は聞き返せないため
- 説明が複雑なとき(条件や用語が 3 つ以上重なる、数値の比較がある、前の説明の訂正を含む、など)は、読み上げで説明しない。外部の読み込みのない HTML に書いて `--open` で開き、声では結論を 1〜2 文で伝えて、「詳しくは開いた画面を見てください」と言う。同じ話題の続きは、同じ HTML に書き足す
- 表、コード、パス、URL、長い一覧は読み上げない。ファイルに書き、`--open` で開いて、声では要点だけを伝える。会話の途中で画面に書いた文章は、利用者に見えていないことがある。一時的な内容は、スクラッチパッドに HTML で書いて開く
- 読み上げる文は、字幕にもそのまま出る。英単語や製品名は、カタカナに直さず、ふつうの表記で書く(例:GitHub、README、TODO)。数は、算用数字でふつうに書く(例:2 つ、0.8 秒)。声では、スクリプトが読みに直す
- 読みがなの表にない英字の語、英字と数字が続いた語、記号は、`{表記|読み}` の形で書く(例:`{listen.py|リッスンパイ}`、`{3GB|さんギガ}`)。何度も使う語は、表に足す(`場面/読みがな.md`)
- 承認が必要な操作(環境の変更、削除、外部への送信、作業フォルダの外への書き込み)は、対象と影響を声で伝えて、返事を聞いてから実行する。確認が画面に出そうな操作の前には、声で「このあと画面に確認が出ます」と伝える
- 返事が相づちだけ(はい、お願いします、了解)でも、会話は続いている。聞き取りを張らずにターンを終えない。次にすることを自分で決めて続ける(作業があるなら、`voice.sh say` で一言伝えて作業に入り、終わったら報告して聞き取る)か、短く次を尋ねて聞き取る
- 認識結果が不自然なとき、承認の返事があいまいなときは、推測で進めずに聞き返す。音声認識には誤変換がある
- 会話の途中で仕組み(スクリプト、設定、スキル)に手を加えたときは、何を変えたかを声でも一言伝える。それ以外の途中経過は読み上げなくてよい

## 守ること

- `tts_provider` に `openai` を指定しない。`OPENAI_API_KEY` を設定しない。接続先にローカル以外の URL を加えない。会話の音声を Mac の外へ出さないため
- `voicemode connect`(外部サービスへのログイン機能)を使わない
- VoiceMode は版を固定して入れてある。更新するときは利用者に確認し、更新後に `voice.sh on` で設定を確かめ直す
- 字幕のファイル(`~/.voicemode/10-voice-captions/`)を自分から読まない(利用者に頼まれたときだけ読む)
- 話す相手、セッションの置き場所、聞き取りの方式、マイクを、自分で変えない(頼まれたときだけ変える)
- 利用者のイヤホンは、話していない間は完全な無音を送ってくる。無音の録音だけでマイクの故障と判断しない
