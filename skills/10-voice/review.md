# 話し方の分析(`/10-voice review`)

1 日分の会話の文字から、利用者の話し方を分析し、改善の案を報告する。対象は、AI への指示の出し方と、話し方そのものの両方。

## 手順

### 1. 利用者に確かめる

会話の文字には、その日のすべてのセッションの発言が入っている。ほかのプロジェクトの業務の内容も含まれる。読んでよいかを、最初に 1 回確かめる。日付の指定がなければ、今日の分を使う。

### 2. 発言と集計を取り出す

```
~/.claude/skills/10-voice/scripts/voice.sh review [YYYY-MM-DD]
```

出力は、数の集計、前回との比較、利用者の発言の一覧(直前の Claude の発言の冒頭つき)。集計は、報告のフォルダにも保存される。

### 3. 分析する

次の 4 つに分けて書く。それぞれ、気づいたこと、実際の発言の例、改善の案を示す。

| 区分 | 見ること |
|---|---|
| AI への指示の出し方 | 何の話かが最初に分かるか(指し示す言葉で始めていないか)。用語が場面ごとに変わっていないか。質問か依頼かが分かるか。決定か感想かが分かるか。1 回の発言に用件が多すぎないか。Claude が聞き返すことになった発言の共通点 |
| 話し方そのもの | つなぎの言葉、文末をぼかす言い回し、1 文の長さ、結論の位置 |
| 音声認識の誤り | 話し方の癖と分けて書く。固有名詞の崩れは、読みがなの表に足すことを提案する |
| Claude の側の問題 | 読み上げが長くて割り込まれていないか。聞き返しが多くないか。利用者の癖ではなく、Claude が直すべきこと |

書き方の決まり:

- 良いところも書く。直す点だけを並べない
- 改善の案は、効きそうな順に並べ、いちばん効きそうな 1 つを最初に示す
- 数は、単純な文字の一致で数えたものだと断る。回数だけで癖と決めつけず、発言の例で確かめる
- 前回の集計があれば、増えた・減ったを書く。発言の数が違うので、100 発言あたりの数で比べる
- 例に引くのは、いま分析しているセッションの発言にする。ほかのセッションの業務の内容は、引用しない
- 最後に、この分析の限界を書く(1 日分であること、相手が AI だけであること、文字だけで声の調子は分からないこと)

### 4. 報告を置いて、開く

報告は、集計の出力にある保存先(`~/.voicemode/10-voice-reviews/YYYY-MM-DD.md`)に書く。会話の内容が入るので、プロジェクトのフォルダやリポジトリには置かない。書いたら `open` で開き、声では、いちばん効きそうな改善と、良いところを、短く伝える。

## 報告の形

```markdown
# 話し方の分析(YYYY-MM-DD)

## もとにしたもの
## まとめ(いちばん効きそうな改善、すでに良いところ、Claude の側の問題)
## 1. AI への指示の出し方
## 2. 話し方そのもの
## 3. 癖ではなく、音声認識の誤り
## 4. Claude の側の問題
## 前回との比較(前回があるとき)
## この分析の限界
```
